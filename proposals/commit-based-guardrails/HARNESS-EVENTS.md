# Hook / event / extension systems of six coding-agent harnesses

Research for a neutral internal event model (`internal/events`) for a multi-harness mock.
Snapshot date: 2026-09-30. Nothing was installed or run; every claim is from docs or source.

**Confidence tags** used throughout:

- **[V]** verified in source code (commit given in section 1) or, for Claude Code, in our own
  controlled runs / binary strings recorded in `claude-mock/EVIDENCE.md` (Claude Code's source is closed).
- **[D]** the vendor's docs say so; not checked against code.
- **[OSS]** seen in open-source third-party code/tests that talk to the real harness (Cursor only).
- **[F]** Cursor forum report, staff-confirmed unless said otherwise.
- **[?]** could not determine.

Prior work reused, not redone: `strategy/.../06_research_harness-adapter-market.md` and
`clusters/harness-agnostic-hook-adapter/studied.jsonl` (normalise-then-translate is what
kenryu42/cc-safety-net, nizos/probity, eqtylab/cupcake, sondera all converge on; cupcake's policies
see the raw payload and are therefore not portable). Probity's canonical type, read at
`nizos/probity@fabb049` `src/types.ts`, is only `Action = {write{path,content}} | {command{command}}`,
`Decision = allow | block{reason}`. That is enough for a PreToolUse guard and nothing else; see section 5.

### 1.1 Which project is "dsh"

Picked `deepseek-ai/deepseek-harness`. Evidence: README says "DeepSeek Harness (`dsh`) is an open-source agent
harness developed by DeepSeek AI"; the binary is `dsh`; it has a hook system. Runner-up
`Hmbown/DeepSeek-TUI` (Rust, 41,044 stars, "coding agent for your terminal") is not named `dsh` and its hooks
were not inspected. Many `dsh-*` community repos exist; they are satellites of the official one. Confidence:
high on the name match, but the repo is 7 weeks old and pre-1.0 (**[?]** how stable any of this is).

**Footnotes (semantic differences)**

- ^c1 Cursor `sessionStart`/`sessionEnd` are fire-and-forget composer-lifecycle events, absent in cloud agents [D]. `sessionStart` output is `env{}` + `additional_context`; there are staff-confirmed bugs where the context is dropped [F 158452, 167274].
- ^c2 `workspaceOpen` fires on every folder change and returns `pluginPaths`; it has no conversation ids [D]. Project-level `workspaceOpen` never runs (reproduced by staff) [F 172939].
- ^c3 `beforeSubmitPrompt` can only block (`continue:false` + `user_message`); it cannot add context; `updated_input` is silently ignored [F 158883]. It does not fire in `-p` mode [OSS agenthooks quirk 31 + F 173219]. A resumed blocked turn re-runs it with an empty prompt (block bypass) [F 173131].
- ^c4 Cursor has both a generic tool hook and per-class hooks. A shell call fires **both** `preToolUse` (`tool_name:"Shell"`) and `beforeShellExecution`; likewise MCP (`MCP:<name>` and `beforeMCPExecution`). Cursor does not de-duplicate; agenthooks uses a 30 s on-disk marker [OSS quirk 2]. `preToolUse` lacks `mcp_server_name`.
- ^c5 `subagentStart` can deny (`ask` treated as deny) but denial is not enforced [F 166143]. Subagents get a fresh `conversation_id` and no reliable link to the parent (ids repeat the conversation id) [F 163054]. Subagent hooks do not fire in cloud agents [F 173362].
- ^c6 Cursor `stop` cannot stop or block; its only output is `followup_message`, auto-submitted as the next user message, bounded by `loop_limit` (default 5 native, `null` for Claude-imported hooks).
- ^x1 Codex `SessionStart` fires **lazily at the first turn**, not at process launch [V `core/src/session/turn.rs` ~L322/L640]. `SessionEnd` `reason` is hard-coded `"other"` [V `session_end.rs` L24].
- ^x2 Codex `PreToolUse` fails **open** on unsupported output. `permissionDecision:"ask"`, `continue:false`, `updatedInput` without `allow`, legacy `decision:"approve"` all mark the hook Failed and the tool runs [V].
- ^x3 Codex `PostToolUse` `block` only replaces the result the model sees; side effects already happened. Hosted tools (web_search, image generation) never fire tool hooks [V].
- ^x4 `notify` is a legacy after-agent hook: argv JSON `{type:"agent-turn-complete","thread-id","turn-id","cwd","input-messages","last-assistant-message"}`, detached, fires after Stop hooks and only if no Stop hook forced a continuation [V `legacy_notify.rs`, `turn.rs` ~L680].
- ^x5 Codex `Stop` `decision:"block"` is a re-prompt: the reason becomes a new synthetic user prompt and the turn re-runs with `stop_hook_active:true` [V].
- ^o1 OpenCode has no SessionStart hook. The approximations (bus `session.created`, or `experimental.chat.system.transform`) differ: the latter fires on every LLM call [V].
- ^o2 `chat.message` fires for the user message and also for synthetic prompts (background-task results). It cannot cancel a prompt without throwing, which fails the whole prompt [V].
- ^o3 `tool.execute.before` fires **before** the permission check; a throw blocks; args can be edited only by mutating `output.args` in place (reassignment is ignored) [V `session/tools.ts:106-111`]. `tool.execute.after` is skipped when the tool throws or is denied. Neither fires for user `!` shell commands (open PR #52277).
- ^o4 `permission.ask` is declared in `packages/plugin/src/index.ts:261` but `grep` finds no trigger call in the runtime; issues #7006, #47674, #47675, #30509, #19453 confirm [V]. A plugin can deny early (throw in `tool.execute.before`) but can never approve.
- ^o5 Sub-agents are child sessions (`parentID`); the child runs a full loop, so `chat.message`, tool hooks and `session.idle` fire again with the child's `sessionID` [V].
- ^o6 `session.idle` is published as a bus event (marked deprecated in the schema but still published); handlers are `void`-called, so they neither delay nor influence anything [V `plugin/index.ts:255-263`].
- ^p1 pi `session_start` fires again on `/reload`; `session_shutdown` also fires on reload/new/resume/fork, not only exit [V].
- ^p2 pi extension slash commands (`registerCommand`) are handled **before** the `input` event; `input` can `transform` the text or mark it `handled` (swallow). `before_agent_start` runs after expansion and is where context or a system prompt is added [V].
- ^p3 pi `tool_call` has no try/catch, so a throwing handler blocks (fail-closed); every other event fails open (error logged, run continues) [V `runner.ts` L1233-1251]. Sibling tool calls run in parallel by default, so handlers interleave [V `agent.ts` L253]. `tool_result` can rewrite `content`/`details`/`isError`.
- ^p4 pi `agent_before_settle` is the only true "stop hook" in the set that can re-prompt; it is skipped if the run was aborted [V `agent-session.ts` L1747-1830]. `agent_end` is not a blocking point.
- ^d1 dsh bridge: `SessionStart` is detached but awaited inside `agent/created`; only JSON `additionalContext` counts (plain stdout is ignored, unlike Claude) [V].
- ^d2 dsh bridge maps `UserPromptSubmit` to `agent/pre-step` "only when the inbox batch is non-empty"; `matcher` is discarded [V].
- ^d3 dsh bridge: `updatedInput` is parsed then logged and **not applied**; `allow` does not pre-approve; `additionalContext` ignored [V].
- ^d4 dsh `SubagentStart/Stop` matcher subject is the constant `general-purpose`; payload carries the child's session id (Claude reports the parent's); no `agent_transcript_path` [V].
- ^d5 dsh `Stop` `deny` calls `agent.steer(reason)`; `stop_hook_active` is always `false` and there is no consecutive-block cap [V].

Numbered; each is concrete and cited. Grouped for reading, numbering is global.

### A. Same name, different moment / different meaning

1. **`SessionStart` is not "process start" everywhere.** Codex fires it lazily at the first turn (`core/src/session/turn.rs` ~L322/L640) [V]; Cursor's is fire-and-forget and absent in cloud agents [D]; OpenCode has none; Claude resumes/forks/compactions/`/clear` all re-fire it with a `source`, and in interactive mode runs it in the background so it can miss the first request [D]. A neutral `SessionStart` must carry `source` and must not promise "before first prompt".
2. **`Stop` means four different things.** Claude: main agent finished responding, not on user interrupt, and it also fires while background tasks run (`F:bgbash`, `F:bgagent`) with `background_tasks`/`session_crons` in the payload [V]. Codex: turn with no follow-up, re-prompts via a synthetic user message [V]. Cursor: `stop` (`status` completed/aborted/error) whose only power is `followup_message` [D]. pi: `agent_before_settle`, skipped on abort [V]. OpenCode: no hook at all, only `session.idle`, unawaited [V]. dsh: `agent/turn-stopping`, with no loop guard [V].
3. **Claude re-prompt is capped; others are not.** Claude overrides the 9th consecutive Stop block (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`, default 8) and streams `"result":""` [V `EVIDENCE.md`]. Cursor `loop_limit` default 5 [D]. dsh bridge: `stop_hook_active` always false, no cap [V] - an always-blocking hook loops until it self-limits. Codex: guard is `stop_hook_active` only [D]; cap not found [?]. The neutral model needs `continuation_count` and a per-harness cap.
4. **A "deny" that still runs the tool - or an "ask" that silently allows.** Codex `PreToolUse` with `permissionDecision:"ask"`, bare `allow`, `continue:false` or `updatedInput`-without-allow is marked Failed and **the tool runs** [V `hooks/src/events/pre_tool_use.rs`]. Cursor `preToolUse` `permission:"ask"` is accepted but not enforced [D]. dsh bridge `updatedInput` is dropped and `continue:false` does not stop [V]. Claude `PostToolUse` `decision:"block"` cannot undo; the tool already ran (same for Codex `PostToolUse` `block`, which replaces the result with feedback) [D/V]. A neutral outcome must say *what the adapter actually enforced*, not what the handler asked for.
5. **Cursor's `subagentStart` deny is not enforced** [F 166143], and Cursor `beforeSubmitPrompt` "Try again" re-runs with an empty prompt, bypassing a block [F 173131]. Guardrails on Cursor need a second, independent defence.
6. **`PostToolUse` vs failure.** Claude fires `PostToolUse` only on success and `PostToolUseFailure` on a tool that ran and failed (measured only for a Bash exiting non-zero); a PreToolUse refusal fires neither [V `EVIDENCE.md` F:bashfail/F:stops]. Codex has no failure event and PostToolUse for a non-zero Bash is unclear [?] (docs claim it fires). OpenCode `tool.execute.after` skips failures and denials [V]. pi `tool_result` covers both with `isError`. dsh fires `PostToolUse` even for a tool that threw [V].
7. **Cursor delivers one tool call as two or three events.** Shell: `preToolUse` + `beforeShellExecution`; MCP: `preToolUse` + `beforeMCPExecution`; Read: `preToolUse` + `beforeReadFile`; edits: `preToolUse` + `afterFileEdit` (the after-only edit has `edits[{old_string,new_string}]`, not a tool input) [D + OSS quirk 2]. No de-duplication by Cursor. A neutral `ToolCall` needs an idempotency key or the adapter must choose one source event per tool class.
8. **pi tool calls run in parallel by default** (`toolExecution ?? "parallel"`, `agent.ts` L253), so `tool_call` handlers for siblings interleave and a handler cannot assume a sibling result exists [V]. Claude fires `PostToolBatch` after a parallel batch; nobody else has an equivalent.
9. **Where the hook sits relative to permission.** OpenCode `tool.execute.before` runs *before* the permission check (so it cannot approve, only throw) [V]. Claude `PreToolUse` `allow` skips the prompt but deny/ask rules still apply, and `PermissionRequest` is a separate event for the moment of prompting [D]. Codex `PermissionRequest` only when about to prompt [V]. Cursor has none. pi has no permission system (README L40-42) [D].
10. **`UserPromptSubmit` capabilities differ.** Claude: block or add context, cannot rewrite the prompt [D]. Cursor: block only, no context, and not fired in `-p` [OSS/F]. Codex: block/context. OpenCode `chat.message`: can edit `parts`, cannot cancel without throwing, and fires again for synthetic prompts [V]. pi `input`: `continue|transform|handled` - the only one that *rewrites* the prompt [V]. Claude also fires it for task notifications with the notification as `prompt` (`F:midturn`, `F:bgagent`) [V].
11. **Compaction hooks: block vs observe vs reshape.** Claude `PreCompact` can block (exit 2 / `decision:"block"`) [V order: PreCompact, summarizer SubagentStop, SessionStart:compact, PostCompact]. Cursor `preCompact` is observational only [D]. Codex `PreCompact`/`PostCompact` `continue:false` stops [V]. pi `session_before_compact` can cancel or supply its own compaction [V]. OpenCode can only add context or replace the prompt, and `experimental.compaction.autocontinue` can suppress the synthetic "continue" turn [V]. dsh: no shell hook [V].
12. **Sessions end differently.** Claude `SessionEnd.reason` is `other` for `-p` [V]. Codex is hard-coded `other` [V]. pi `session_shutdown` also fires on reload/new/resume/fork [V]. OpenCode has no SessionEnd (only `session.deleted`/`dispose`). dsh bridge has none.

### B. Tool names and shapes

13. **The same action has six names.** Shell: Claude `Bash` (and `PowerShell`), Cursor `Shell`, Codex `Bash` (canonical, from `exec_command`; matcher aliases only) with `tool_input:{command}`, OpenCode `bash`, pi `bash`, dsh `bash`/`pwsh`. File write/edit: Claude `Write`/`Edit`/`NotebookEdit`; Cursor `Write` for both (Claude `Edit` and `Write` both map to Cursor `Write`; `Glob` has no mapping) [D]; Codex `apply_patch` with `tool_input.command = <patch text>` and matcher aliases `Write`/`Edit` [V `core/src/tools/hook_names.rs`]; OpenCode `edit`/`write`/`apply_patch` (`patchText`) - which one depends on the model [V `registry.ts:296-300`]; pi `edit`/`write`; dsh `edit`/`write`/`str_replace_editor`. A neutral `ToolKind` must be derived from the *effect* (shell, file-write, file-read, search, web, agent-spawn, mcp, other), not the name; and a patch-shaped tool (Codex, OpenCode) touches several files, so a single `path` field is a lossy mapping.
14. **Argument field names differ.** Claude `file_path` (always absolute; `~`/relative expanded before hooks) [D]; OpenCode `filePath`, `oldString`, `newString` [V]; Cursor `file_path` on `beforeReadFile`, `working_directory` on shell [D]; dsh has its own (`edit`/`read` are not `file_path`) [V]; pi `bash.command` confirmed, other fields not enumerated [?]. Cupcake shows what happens if you skip normalisation (policies stop being portable).
15. **Serialisation of `tool_input`/`tool_output` differs.** Cursor `beforeMCPExecution.tool_input` is a JSON *string* but `preToolUse.tool_input` is an object; `postToolUse.tool_output` is a stringified JSON [D + OSS quirk 5]. dsh `tool_response` is flat text [V]. Claude `tool_response` is a tool-specific object (`{stdout,stderr,interrupted,isImage,noOutputExpected}` for Bash) [V].
16. **MCP naming.** Claude `mcp__<server>__<tool>` with `mcp_server{name,source}` in the payload [D]; Codex the same `mcp__` form [V]; dsh the same [D]; Cursor `MCP:<tool>` on `preToolUse`, server only on `beforeMCPExecution`/`afterMCPExecution` [D + F 167261]; OpenCode `<sanitized server>_<tool>` (single underscore, non-alnum -> `_`) [V `mcp/catalog.ts:117-119`]; pi `registerMcpServer` / `mcp.json`, naming not verified [?].
17. **Tools with no hooks.** Codex hosted tools (web_search, image generation) skip tool hooks [V]; Codex `write_stdin` has no PreToolUse [V]; Claude `EndConversation` skips both, and `@`-referenced files enter context with no tool call [D]; Cursor `AskQuestion` fires nothing [OSS quirk 16]; OpenCode user `!shell` commands fire only `shell.env` [V], and session-title generation bypasses plugin hooks (issue #46115); pi user `!bash` fires `user_bash` not `tool_call`. No harness can promise "every side effect passes a PreToolUse".
18. **Nested tool calls.** pi `ctx.executeTool` fires `tool_call`/`tool_result` with `parentToolCallId` and ids `<parent>/<n>` [V]; OpenCode code-mode nested tools may bypass permissions (issue #47177). Neutral `ToolCall` needs a `parent_call_id`.

### C. Identity, sessions, sub-agents, background work

19. **Ids are inconsistent or missing.** Claude: `session_id` on all events, `prompt_id` since 2.1.196, `tool_use_id` on PreToolUse/PostToolUse but **not** on PermissionRequest [D]. Codex: `session_id` (= root thread id), `turn_id` (not on SessionStart/End), `tool_use_id` (not on PermissionRequest); `transcript_path` may be null; exec `--json` item ids are a synthetic counter `item_0…` and cannot be correlated with hook `tool_use_id` [V]. Cursor: `conversation_id` stable, `generation_id` per user message; `session_id` present in real payloads but not in the docs; `tool_use_id` on tool hooks; identity fields sometimes blank [F 167095]; `transcript_path` null in cloud agents. OpenCode: `sessionID`, `callID`, `messageID?`; **no `cwd` in hook input** [V]. pi: no session id in any event payload (only via `ctx.sessionManager`, or `PI_SESSION_ID` env in the bash tool), no run id, no turn id (only `turnIndex`) [V]. dsh: bridge base = `session_id`, `transcript_path:""`, `cwd`, no `permission_mode` [V].
20. **Sub-agents are represented four ways.** (a) Events with `agent_id`/`agent_type` plus the parent's `session_id`: Claude [V], Codex [V]. (b) Events with the *child's own* ids: Cursor (fresh `conversation_id`, parent link unreliable [F 163054]), dsh (child session id, `agent_type` constant `general-purpose`) [V]. (c) A child *session* with `parentID`, no start/stop event: OpenCode [V]. (d) Not a concept: pi (example extension spawns separate `pi` processes) [V]. Claude adds a twist: a `SubagentStop` fires for internal agents with empty `agent_type` (prompt suggestions, `/btw`, and the compaction summarizer, `EVIDENCE.md`) [D/V], and a top-level `--resume` fires no SubagentStart/Stop [V].
21. **Claude sends every event's `transcript_path` as the *session's* path for sub-agent events; the sub-agent is named by `agent_id`** (its own file is `agent_transcript_path`, only on SubagentStop) [V EVIDENCE]. Codex's `agent_transcript_path` likewise only on SubagentStop [V]. Cursor's `agent_transcript_path` on `subagentStop` only [D].
22. **Background tasks: Claude has a first-class model; nobody else does.** Claude's Stop/SubagentStop carry `background_tasks[]` and `session_crons[]`, Stop fires at *every* end of turn (even with background work pending), finished tasks start new turns (`origin.kind:"task-notification"`), and `-p` waits for background agents (10 min ceiling) [V]. Codex has background terminals but no hook [V]; dsh `job_*` tools notify by `agent.inject()` with no hook [V]; OpenCode background subagents need `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS` and re-enter as a synthetic user prompt [V]. So "the turn ended" is not "the work ended" for Claude only.
23. **Resume/fork.** Claude `--fork-session` needs `--resume`, else plain `startup`; fork of a compacted session copies the boundary; `--resume <unknown>` exits 1 and fires SessionEnd but not SessionStart [V]. Codex has `fork` source and `thread/revert` writes a new rollout [V]. pi branches in place inside one file (`/tree`, `parentId`) and `/fork` creates a new file with `parentSession` [V]. OpenCode `Session.fork` creates a top-level session (no `parentID`) and emits `session.created` [V]. A tree-shaped transcript (pi, OpenCode messages) does not map to Claude's linear-with-`logicalParentUuid` JSONL.

### D. Output streams and transcripts

24. **Only some harnesses expose tool hooks in their non-interactive stream.**
   - Claude `-p --output-format stream-json`: `system/init`, `system` task frames (`task_started`, `task_updated`, `task_notification`), `hook_started/progress/response` for SessionStart/Setup, `permission_denied`, `api_retry`, `result` [D/V].
   - Codex `exec --json`: `thread.started`, `turn.*`, `item.started/updated/completed` (`command_execution`, `file_change`, `mcp_tool_call`, `collab_tool_call`, `web_search`, `todo_list`); **hook started/completed are dropped** (`event_processor_with_jsonl_output.rs` L474) [V].
   - pi `--mode json`: session events (`agent_start`, `turn_*`, `message_*`, `tool_execution_*`, `agent_end`, `agent_settled`); **no `tool_call`/`tool_result`** extension events on the wire [V].
   - OpenCode `run --format json`: `{type,timestamp,sessionID,…}` with `tool_use` (completed/error only), `step_start/finish`, `text`, `reasoning`, `error`; child-session parts skipped [V].
   - Cursor `-p --output-format stream-json`: `system/init`, `user`, `assistant`, `tool_call{started|completed}` with per-tool keys (`readToolCall`, `writeToolCall`, or `function{name,arguments}`), `result`; thinking suppressed; shell shape undocumented [D/?].
   - dsh `--json`: `session`, `status`, `text`, `thinking`, `tool_call`, `tool_result`, `final`, `error`; text is emitted at step commit, not per token; a failed turn can still end with `final` and no `error` [V].
   A mock's "normalised events" for a run are therefore *not* the hook events; they must be a third stream (or reconstructed from the transcript).
25. **Transcript storage.** Claude `~/.claude/projects/<cwd>/<session>.jsonl` (+ `subagents/agent-<id>.jsonl`, `.meta.json`) written asynchronously and may lag a hook [D/V]. Codex `~/.codex/sessions/YYYY/MM/DD/rollout-<ts>-<thread>.jsonl` (maybe `.jsonl.zst`), format "not a stable interface"; hook events are **not persisted** [V]. Cursor: Claude-compatible JSONL for headless [D], user text wrapped in `<user_query>` [OSS]; real path root [?]. OpenCode: SQLite `~/.local/share/opencode/opencode.db` (macOS path [?]), messages/parts as JSON columns [V]. pi: `~/.pi/agent/sessions/--<cwd>--/<ts>_<id>.jsonl`, v3, `{id,parentId}` tree [V]. dsh: `session.v3|v4.jsonl.zstd` under an unconfirmed root; hooks get `transcript_path:""` [V/?].
26. **Hook output leaves a record only in Claude.** Claude writes `hook_success`/`hook_non_blocking_error`/`hook_blocking_error`, `stop_hook_summary`, `hook_additional_context` attachments to the transcript (only for SessionStart, UPS, PreToolUse, PostToolUse, Stop, SubagentStart/Stop) [V EVIDENCE]. Codex `HookStarted/Completed` are transient. dsh writes `hook/invoked`+`hook/result` only inside a turn [V]. Anything that inspects "what hooks did" from the transcript works on Claude only.

### E. Configuration and enforcement reality

27. **Config scope and trust.** Claude merges user + project + local + managed + plugin + skill/agent frontmatter [D]. Codex merges all layers, and **untrusted or modified hooks are silently skipped** (needs `--dangerously-bypass-hook-trust` in unattended `exec`) [V `discovery.rs` L796-822]. Cursor: project hooks only in trusted workspaces; cloud agents ignore `~/.cursor/hooks.json`; **a URL in any hook command drops the whole `hooks.json` with no log** (agenthooks quirk 29, not reproduced) [OSS]. pi project resources load only after a trust decision [V]. dsh: one process-level file, off by default, malformed matcher rejects everything [V]. OpenCode/pi are in-process code with full OS permission; Claude/Cursor/Codex hooks are separate processes.
28. **Compatibility layers create ambiguity about which protocol you are speaking.** Cursor reads Claude `settings.json` hooks and maps 8 events; it accepts Claude's nested `hookSpecificOutput` [D]. But the mapped payload's `tool_name` is `Shell` while the matcher was converted from `Bash`, `cwd` may be empty, exec-form `args` are lost, and converted hooks are always `failClosed:false` (imported hooks fail open) [F 173171, staff: "isn't intended"]. Cursor also sets `CLAUDE_PROJECT_DIR` so env sniffing can't identify it [OSS quirk 20]. dsh and Codex speak Claude-shaped JSON with subtly narrower semantics (Codex `permission_mode` only `default`/`bypassPermissions`; dsh omits it). A "Claude-shaped handler" is not the same as "Claude".
29. **Fail-open/closed defaults disagree.** Claude: non-2 exit and timeout = proceed (but a *callback* timeout on PreToolUse blocks) [D]. Cursor: fail-open unless `failClosed:true`; with it, empty stdout blocks [OSS defenseclaw]; invalid JSON on permission hooks blocks [D]. Codex: Failed = fail-open [V]. pi: `tool_call` throw = block, everything else fail-open [V]. OpenCode: any throw aborts the operation, including `chat.params`/`system.transform` (breaks every LLM call) [V]; no timeouts on OpenCode/pi means a hung handler hangs the run [V].
30. **Docs drift the neutral model must not inherit.** OpenCode docs list a handful of hooks; code has ~15, and `permission.ask` is dead [V]. pi's old "hooks" are gone and "no MCP" is stale (MCP now built in) [V]; `docs/extensions.md` no longer documents per-event contracts, `types.ts` is the authority. Codex docs list `SessionStart` sources without `fork` [V]; `prompt`/`agent` hook types parse then get skipped [V]. Cursor docs omit `session_id`/`cwd` from common fields, omit `additional_context` on `preToolUse`, and list subagent hooks as supported in cloud agents where they don't fire [F]. dsh README says "23 of 30 events unsupported"; code supports 7 [V]. Claude docs vs binary: our own EVIDENCE shows several rows where the docs were incomplete (e.g. `background_tasks` entry shape, SubagentStop for the summarizer).
31. **Env vars given to hooks.** Claude: inherited env + `CLAUDE_PROJECT_DIR`, `CLAUDE_ENV_FILE` (SessionStart/Setup/CwdChanged/FileChanged only), `CLAUDE_CODE_REMOTE`, plugin vars; **no model var** [D]. Cursor: `CURSOR_PROJECT_DIR`, `CURSOR_VERSION`, `CLAUDE_PROJECT_DIR`, `CURSOR_USER_EMAIL`, `CURSOR_TRANSCRIPT_PATH`, `CURSOR_CODE_REMOTE`; `sessionStart` `env{}` propagates to later hooks [D]. Codex: inherited (minus 5 credential vars) + plugin vars `PLUGIN_ROOT`/`CLAUDE_PLUGIN_ROOT`/`PLUGIN_DATA`/`CLAUDE_PLUGIN_DATA`; **no `CODEX_THREAD_ID` for hooks** although the model's shell tool child gets `CODEX_THREAD_ID`, `CODEX_SESSION_ID`, `CODEX_VERSION`, `CODEX_SANDBOX` [V]. OpenCode: none for plugins (in-process); bash tool gets `process.env` + `shell.env`, no session id exported [V]. pi: `AI_AGENT=pi`, `PI_CODING_AGENT=true` process markers; bash tool only gets `PI_SESSION_ID`, `PI_SESSION_FILE`, `PI_PROVIDER`, `PI_MODEL`, `PI_REASONING_LEVEL` [V]. dsh bridge: `CLAUDE_PROJECT_DIR` only [V]. Session identity therefore reaches child processes only via stdin JSON (Claude, Codex, Cursor, dsh) or env (pi, Codex model shell), never uniformly.

### F. Things that cannot be mapped

32. **Claude concepts with no home elsewhere:** `PermissionDenied`+`retry`, `WorktreeCreate` (a hook that *replaces* git worktree creation and returns a path), `TaskCreated/Completed`, `TeammateIdle`, `Elicitation`, `ConfigChange`, `InstructionsLoaded`, `PreModelSwitch` (block), `MessageDisplay.displayContent`, `terminalSequence`, `sessionTitle`, `watchPaths`, `initialUserMessage`, `reloadSkills`, `CLAUDE_ENV_FILE`.
33. **Other harnesses' concepts Claude cannot express:** pi `input` *transform* of the prompt; pi `tool_result` rewriting `isError`/`content`/`details` (Claude only replaces output shape via `updatedToolOutput`); pi/dsh/OpenCode per-LLM-request mutation (`context`, `chat.params`, `agent/request`); pi `agent_before_settle` continuing with *entries*; pi `terminate` on a tool batch; Codex `Interrupt`; Cursor `afterFileEdit` diffs and `followup_message` with a `loop_limit`; OpenCode `experimental.text.complete` rewriting assistant text; Cursor `preToolUse.agent_message` vs `user_message` (separate model-facing and user-facing reasons; Claude's PreToolUse has one reason whose audience depends on the decision).

## 5. Implications for a neutral model

Current plan: Go types in `internal/events` named and shaped after Claude's hook semantics, each harness adapter converting wire <-> them, an event a harness lacks mapping to nothing.

### Where the plan holds

- For the **hook-protocol** harnesses (Codex, dsh bridge, Cursor-with-import) the wire is already Claude-shaped, so a Claude-reference model plus adapters is the natural fit (this is also how cc-safety-net, probity, sondera converge). The 8-event core - SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, SubagentStop (+Start), PreCompact, SessionEnd - is present on at least four of six harnesses.
- A tool-input/output normalisation layer is mandatory (gotchas 13-16), and cupcake proves it must reach the *policy input*, not just the decision.

### Where it breaks (lossy or false mappings)

1. **"Missing event maps to nothing" conflates three different situations.** (a) The harness truly has no such moment (Codex has no PostToolUseFailure). (b) The moment exists but is observation-only (OpenCode `session.idle`, Cursor `preCompact`). (c) The moment exists under a different shape (OpenCode subagent = child session; pi `agent_before_settle`). Dropping all three silently makes a mock claim "Stop fires and can block" on OpenCode, which is false. Need a per-harness, per-event **capability** table: `{fires, can_block, can_modify_input, can_add_context, can_continue, fail_mode, async}` with values `yes | observe | no | unreliable`.
2. **Claude-shaped outcomes hide enforcement gaps.** The neutral `Result` must separate *requested* from *enforced*: Codex `ask` on PreToolUse and dsh `updatedInput`/`continue:false` are requested-but-not-enforced (gotchas 4). Add `Enforced{Applied, Ignored, Failed(reason)}` so the mock can reproduce "tool ran anyway" and a checker can flag a rule that cannot bite on that harness.
3. **Claude's `decision` is one word for two different things** (block a pending action vs. re-prompt at end of turn vs. reject-with-feedback after the fact). Cursor `stop`, Codex `Stop`, dsh `Stop` express "continue" as *injecting a user message*; Claude expresses it as a block with a reason; pi as `continue:true`+entries. Neutral outcome: `Continue{Feedback, Kind: block_stop | followup_prompt}` and a count.
4. **`Ask` is not universal** and its audience differs (Claude: reason shown to user for ask, to model for deny; Cursor: separate `user_message`/`agent_message`). Model reason as `{ForUser, ForModel}`.
5. **Tool identity.** Claude tool names as the neutral vocabulary would force `Bash` for Cursor `Shell`, and `Edit`/`Write` for Codex `apply_patch`, false for multi-file patches. Use a neutral `ToolKind` + `Effects []Effect` (`WritesFile{Path}` list, `RunsCommand{Cmd}`, `Network`, ...), and keep `NativeName` and `NativeInput` verbatim for round-tripping (probity's `Action` is too small; it has no read, no MCP, no sub-agent).
6. **Ids.** Claude-shaped `session_id`/`tool_use_id` are missing on pi events, Codex PermissionRequest, Cursor blank cases, OpenCode `cwd`. Make ids optional with a `Provenance` (`native | derived | synthetic`) and never treat absence as an error.
7. **Sub-agents.** Claude's `agent_id`+`agent_type` on *every* event in a sub-agent is the odd one; other harnesses give a child session. Neutral: `Actor{SessionID, ParentSessionID?, AgentID?, AgentType?}` on every event, plus `SubagentStart/Stop` synthesised by the adapter where the harness only has session parenthood (OpenCode `session.created`+`parentID`, `session.idle`) - flagged `Synthesised`.
8. **Turn vs run vs settle.** Claude `Stop` = end of turn *or* re-fire after each background completion; pi splits `agent_end` / `agent_before_settle` / `agent_settled`; Codex `task_complete` and `Stop` differ; OpenCode has `busy/idle` transitions per LLM step. Neutral model needs an explicit `TurnEnd{Settled bool, PendingBackground []Task}` or the mock cannot reproduce "Stop fires while background work runs" (gotcha 22).
9. **Multiple-handler resolution is per-harness behaviour, not a detail:** parallel + precedence (Claude), concurrent + last-`updatedInput`-wins (Codex), inverted merge (Cursor), serial + most-restrictive (dsh), sequential threaded `output` (OpenCode/pi). A mock that runs several guardrails must implement the *harness's* rule, so `Resolve()` belongs in the adapter.
10. **Fail mode, timeout and hang** (gotcha 29) must be adapter-level facts, since a guardrail that "blocks" only when it exits 2 in time is not a block on Cursor without `failClosed`.
11. **Non-hook streams.** The neutral model in the plan covers hooks. But each harness's *run stream* (gotcha 24) and *transcript* (25) are separate wires with different content (Codex drops hook events; pi drops `tool_call`). Add a second neutral family, `Observation` (message, tool_started/finished, turn, usage, task), distinct from `Hook`. Claude-only records (hook attachments, `stop_hook_summary`) are outputs of the mock's Claude adapter, not neutral events.
12. **Events that are neither in Claude nor mappable** but matter to guardrails: Cursor `beforeReadFile`/`afterFileEdit`, Codex `Interrupt`, OpenCode `shell.env`, pi `user_bash`/`context`. Either add `FileRead`, `FileEdited`, `Interrupt`, `UserShell` as optional neutral events or accept that a guardrail cannot see them; do not fold them into `PreToolUse`, because Cursor then double-fires (gotcha 7).

### Minimal additions that fix the most

- **`Capabilities` matrix** per harness x event (see 1), exported as data, used by the mock to decide *whether to fire* and *whether a block is honoured*.
- **`Outcome` = {Decision: none|allow|deny|ask|defer, Reason{ForUser,ForModel}, UpdatedInput?, UpdatedOutput?, AddedContext[], Continue?{Kind,Feedback}, StopAll?, Enforced}`**. One struct; adapters fill what their wire can carry and set `Enforced` honestly.
- **`Event` envelope**: `{Kind, Native{Name,Payload json.RawMessage}, Session, Turn?, Actor, Tool?{Kind, Effects, NativeName, NativeInput, CallID?, ParentCallID?, MCP?}, Provenance}`. Always keep `Native` so adapters round-trip and rules can opt into native fields.
- **`ToolKind`+`Effects` normaliser** as a shared package with golden tests from real payloads (Cursor fixtures from agenthooks/cc-safety-net; Codex generated JSON schemas in `codex-rs/hooks/schema/generated`; Claude `EVIDENCE.md` fixtures).
- **Synthesised events flagged** (`Synthesised:true`) instead of "maps to nothing" when the adapter can derive them (subagent start/stop on OpenCode, PostToolUseFailure on OpenCode/pi from `error` state).
- **Do not use Claude's exit-code protocol as the neutral one.** It is one transport. Codex/Cursor/dsh share it; OpenCode/pi are in-process return/mutate/throw. Keep transports in adapters.

### Order of adapters by value and fit (popularity is a signal, not a decision)

dsh (240k stars but 7 weeks old, pre-1.0) and OpenCode (211k) are the largest; Claude Code (148k) reference; Codex (127k) is closest to Claude on the wire; pi (110k) is the most different (in-process, richest event set, has the only real settle hook); Cursor (33k repo stars, closed, most quirks) is the least trustworthy target for a *mock*, since much of its real behaviour is only known from forum bug reports. Prior strategy work (`portability-is-not-rewarded.md`) says portability by itself is not rewarded by adoption; that is outside this document's scope.
